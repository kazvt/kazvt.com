# Live player submissions

## Normal workflow

1. Deploy the patch together. Refresh both host pages and all three private player pages. Existing authenticated v2 invitations remain valid; no credential rotation or host policy changes are needed.
2. On `/rg/console/`, expand **PRIVATE PLAYER ROOM / READER** and start the online room if stopped. Send Kaz, Faroe and Erin their individual **COPY LINK** invitations privately. Keep either initialized host page open (both must be the same browser profile and origin if using two).
3. Start Berryblast or Red Handed, or use `trivia <round> <difficulty>` / PRESENT from the authored editor. All regular live question formats (including drawing, composition, sorting, matching, timelines, sequences, images, video and numeric guesses) use the same authenticated `/rg/player/` controller. No task-file exchanges or player-name selectors are needed in normal play. A legacy `/rg/draw/`, `/rg/place/` or `/rg/sort3/` URL containing a valid private invitation redirects to that same controller. A bare legacy URL remains an explicitly offline task-file fallback.
4. Contestants enter/select/draw their own answers and submit. A sending state does not mean the host saved anything. Each contestant sees only their own saved answer or numeric feedback. The console's private room shows connected/offline and waiting/saved. `answers` opens a private live answer viewer for the active round; `trivia answers` opens the most recent trivia responses even if another activity is active. The staff editor's LIVE ANSWERS also shows visual responses. Scores remain manual; the stage intentionally shows the selected contestant’s live work for numeric guessing, drawing, placement and sorting; other card-game reveal rules remain unchanged. Card audience voting and the special 00/0 editor/instruction pages are not remote contestant-answer rounds.

## Reliability and boundaries

- The authenticated reliable binary PeerJS channel remains the sole normal cross-device transport. PeerJS handles serialization and chunking. The host authenticates the seat, checks the round, validates the answer shape and size, and serializes writes under the shared Web Lock. No client-provided seat override, extra metadata, or correct-answer field is trusted.
- A unique request ID correlates acknowledgements; numeric attempt IDs and the one-answer-per-seat rule continue to make retries idempotent. A successful acknowledgement alone does not clear the outbox: the player waits for the authoritative snapshot containing its saved answer or matching numeric attempt. A late ACK cannot resolve another request. If the host rejects or storage fails, no success is displayed. If confirmation is absent for eight seconds, the player reconnects with backoff and retries the same saved request only if the current round still accepts it. Pending submissions and unfinished drafts use seat/room/round-scoped sessionStorage, subject to browser availability. Closing the tab may discard its session; accepted host answers persist. Switching activities does not send the old pending answer into the new round.
- Drawing and placement coordinates are normalized; drawings accept at most 80 strokes and 1,400 total points (500 per stroke), placements at most 64 entries. The live and offline renderers preserve intrinsic image aspect ratio, uses one primary drawing pointer, offers undo/clear, and retains draft state on ordinary re-renders/refresh. The host rejects incomplete question structures rather than presenting an impossible answer form. Correct answers, other seats' answers and unrevealed sequence items remain private. Sequence questions still have one final response per seat, not one response per slide.
- Offline packets are hidden on the normal live sending path and available when disconnected. The old file-task workflow is collapsed under OFFLINE FILE FALLBACK. Offline packets are validated by the same host receiver when imported, but legacy JSON files remain a separate manual fallback, not authenticated live answers. Do not share either private link or packet on stream.
- GitHub Pages remains static, and PeerJS Cloud/CDN and network reachability remain external dependencies. This patch does not install TURN, a database, or a VPS. No full live cross-device transport/production scene verification was possible in the patch environment; tests exercise actual authentication and game modules with mocked peers and the actual DOM renderer in Chromium.
