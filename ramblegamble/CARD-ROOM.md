# Card room (GitHub Pages, no VPS)

The existing `/rg/` arcade is the host/audience display. Its Card Games host tab is now a nonmodal side panel; the table itself has a screen-facing, tabletop-anchored HUD. The private player route is `/rg/player/`. No accounts, database, migration, server, repository writes, or API keys are needed.

1. Open `/rg/`, choose the card table and open HOST (or the Card Games host tab). Pick Berryblast or Red Handed. Add prompt/deck lists as usual.
2. Click **START ONLINE ROOM** in the card host panel on `/rg/` or expand **PRIVATE CARD ROOM / READER** on `/rg/console/`. Send the three **COPY LINK** links individually to Kaz, Faroe and Erin (private Discord DMs, not the public channel). The links are bearer credentials for those seats. Do not display them in a stream. You can share them before starting a round.
3. Start the game. Each player opens their link on their device. Berryblast: type and press Enter or Submit. Red Handed: choose one of five private evidence cards and Submit. A confirmed submission is locked. The host sees progress; after all three accepted responses, the display automatically reveals anonymous answers underneath the Berryblast prompt or as Red Handed evidence cards. Existing audience voting and Reveal Results still work. Next rounds arrive on the same connection.
4. Keep at least one host page open and awake. Both `/rg/` and `/rg/console/` in the **same browser profile and origin** share a room ID, seat credentials and round state via localStorage. One tab is elected ACTIVE READER using an exclusive Web Lock; the other shows STANDBY. Closing or navigating away from the reader releases the lock and the standby takes over automatically with the same invitation links. Players using live invitations reconnect automatically with backoff and resend unacknowledged submissions for the same round. There may be a brief interruption while PeerJS releases the old peer ID. A suspended/frozen browser tab may delay handoff; close it if necessary. STOP ONLINE ROOM on either page stops live networking for both; restart from either page. When the room is enabled, reopening either page resumes the election. The console can receive answers while `/rg/` is closed; reopen `/rg/` to display saved submissions. The existing game controls remain on `/rg/`.
5. Upgrade note: the first upgraded host page imports its previous sessionStorage room if available; otherwise it creates a shared identity. If the old invitation links matter, update and reload the original `/rg/` host tab first, then the console. Close all old-version host tabs before starting. Both host pages must be on the same deployed origin (e.g. kazvt.com), not separate browser profiles or private windows. Web Locks requires a supported secure browser context; if unavailable the online reader is disabled rather than risking duplicate readers. The offline fallback remains usable with working storage.

## If live networking fails

The online path uses the pinned PeerJS 1.5.5 browser bundle (jsDelivr) and the public PeerJS Cloud signaling service with WebRTC data channels. These are third-party services; direct peer-to-peer connectivity depends on network/firewall/NAT conditions. No guarantee of availability or relay coverage is made. There is no self-hosted signaling or TURN server and no hidden VPS requirement.

The independent fallback works without PeerJS: after starting each round, use **OFFLINE ROUND** for each player and share that fresh link privately. It includes only that seat's prompt/hand. The player submits locally and copies the generated private packet into a DM; the host pastes it into **IMPORT ANSWER**. It is not accepted until the host imports it. Long offline links/packets may exceed chat message length; send them as a text file if necessary. Manual host entry is also retained. Live invite links are short and contain no hand or prompt; round-specific offline invites are longer. Old packets are rejected automatically.

## Trust and implementation

Host validates the 128-bit random room ID and per-seat tokens, current unique round ID, one accepted answer per player, max text length and exact membership in a Red Handed hand. The host sends each authenticated player only the prompt, its own evidence options, phase and submission status. It never broadcasts other hands, answers or scores to remote players. Browser-local state remains the original host storage; same-origin BroadcastChannel is not a cross-device network. The invitation is a bearer link, not a verified identity or strong anti-cheat system; anyone with that link can submit as that seat. Share it privately and stop the room, close all host tabs, and clear the shared `rg-card-room-v1` site-storage key before reopening if a link leaks (new invitations are then required). URL fragments are not sent in normal HTTP requests, but local browser history and whoever receives the link can see them. The public signaling/CDN services remain trusted dependencies for live play.
